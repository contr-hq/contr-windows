# Contr for Windows

WinUI 3 desktop client for [Contr](https://github.com/contr-hq/contr). It talks to the `contrd` daemon only through the
C# SDK the core repository generates, over a per-user named pipe.

## Status

First working client: containers (start, stop, restart, delete, logs), images (pull with progress, delete), volumes
(create, delete) and networks (delete), all following the daemon's Watch streams. The status bar shows the engine state
and starts or stops the engine; the tray keeps Contr reachable while its window is closed. Until the core's WSL backend
lands, run it against `contrd --backend fake`.

Next: the exec terminal (WebView2 + xterm.js), Compose, Kubernetes, onboarding, settings, and a Velopack installer that
bundles a pinned core release.

## Build and run

Windows 10 1809 or later with the .NET 10 SDK (see `global.json`) and the Windows App Runtime 2.3 or later.

```pwsh
dotnet build Contr.slnx
dotnet test Contr.slnx
dotnet format Contr.slnx --verify-no-changes --severity warn --exclude gen
```

To run against fixture data, build `contrd` with the fake backend in a checkout of the core repository, then start
both with the script:

```pwsh
cargo build -p contr-daemon --features fake
dotnet build src/App/Contr.App/Contr.App.csproj -p:Platform=x64
pwsh scripts/run-fake.ps1 -Contrd C:\src\contr\target\debug\contrd.exe
```

Without the script the app connects to the daemon at `CONTR_HOST`, else the one its discovery file names, else the
per-user default pipe, and starts `contrd.exe` (beside the app, else on `PATH`) when nothing answers there.

## The SDK

`gen/Contr.Sdk` is generated by the core repository's `contr-sdkgen`; `gen/CORE_COMMIT` names the commit. Regenerate
it from a core checkout instead of editing it:

```bash
scripts/update-sdk.sh ../contr origin/main
```

CI regenerates it from `gen/CORE_COMMIT` and fails when the committed copy differs.
