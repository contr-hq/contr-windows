# Contr for Windows

WinUI 3 desktop client for [Contr](https://github.com/contr-hq/contr). It talks to the `contrd` daemon only through the
C# SDK the core repository generates, over a per-user named pipe.

## Status

The design's shell, Containers (grouped by Compose project, with a page per container: logs, inspect, a terminal and
stats), Images (pull with per-layer progress, prune), Volumes and Networks, all following the daemon's Watch streams.
The title bar searches containers, images, volumes and networks; the status bar shows the engine state and starts or
stops the engine; the tray keeps Contr reachable while its window is closed. Until the core's WSL backend lands, run it against `contrd --backend fake`.

Also: Compose projects from the containers' Compose labels, Troubleshoot (the engine's failure, the checks the client
can make, its own log), the tray flyout with the running containers, and the Kubernetes page's layout.

The first run opens a setup (this PC's checks, the engine's setup with the daemon's progress, the command-line tools,
which of your WSL distributions reach the engine, and start at sign-in), and Settings has the design's tabs, with a
switch per WSL distribution where the daemon integrates them.

Next: a Velopack installer that bundles a pinned core release.
Screens and actions whose daemon API does not exist yet (Run, factory reset, diagnostics, Kubernetes, Compose up and
down, resources, proxies, engine configuration, updates) show their layout with the actions disabled.

The terminal is [xterm.js](https://github.com/xtermjs/xterm.js) (MIT) in WebView2, vendored with its licence under
`src/Modules/Containers/Contr.Modules.Containers.UI/Terminal/xterm` at the versions `VERSIONS` there names.

The icons are a font built from [Fluent UI System Icons](https://github.com/microsoft/fluentui-system-icons) (MIT),
whose SVGs and licence are in `assets/icons`. After adding or changing an SVG there, list it in
`assets/icons/icons.json` (new icons at the end, so the others keep their code points) and rebuild the font and its
`ContrIcons` glyph table:

```bash
uv run --with fonttools==4.60.1 scripts/build-icon-font.py
```

## Build and run

Windows 10 1809 or later with the .NET 10 SDK (see `global.json`) and the Windows App Runtime 2.3 or later.

```pwsh
dotnet build Contr.slnx
dotnet test Contr.slnx
dotnet format Contr.slnx --verify-no-changes --severity warn --exclude gen
```

To run against fixture data, build `contrd` with the fake backend in a checkout of the core repository, then start
both with the script:

```pwsh
cargo build -p contr-daemon --features fake
dotnet build src/App/Contr.App/Contr.App.csproj -p:Platform=x64
pwsh scripts/run-fake.ps1 -Contrd C:\src\contr\target\debug\contrd.exe
```

Without the script the app connects to the daemon at `CONTR_HOST`, else the one its discovery file names, else the
per-user default pipe, and starts `contrd.exe` (beside the app, else on `PATH`) when nothing answers there.

## The SDK

`gen/Contr.Sdk` is generated by the core repository's `contr-sdkgen`; `gen/CORE_COMMIT` names the commit. Regenerate
it from a core checkout instead of editing it:

```bash
scripts/update-sdk.sh ../contr origin/main
```

CI regenerates it from `gen/CORE_COMMIT` and fails when the committed copy differs.
